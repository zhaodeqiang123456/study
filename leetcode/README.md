# LeetCode 代码存放约定

每道题两个文件，放在本目录。这里是一个**独立模块**（`module leetcode`），跟 `project/` 里的服务代码互不影响。

## 命名

- 解法：`<四位题号>-<英文名小写连字符>.go`，例如 `0001-two-sum.go`
- 自测：`<同名>_test.go`，例如 `0001-two-sum_test.go`

题号补零到四位，方便目录按顺序排列、以后回头看错题。

## 文件里写什么

解法文件顶部一段注释，写清：题号 + 题名 + 难度、我的思路、时间/空间复杂度、是否独立完成（是 / 看了提示 / 看了题解）。函数名用题目对应的英文名，不要写成 `main`。

自测文件里放你自己造的用例，**必须包含**：题目给的例子、边界（空输入 / 只有一个元素 / 重复元素 / 极值）、以及你一开始写错过的那个用例。写过一次错解就留一个用例把它钉死。

## 怎么跑

```powershell
cd D:\project\study\leetcode
go test ./...           # 跑全部题的自测
go test -run TwoSum -v  # 只跑某一道
```

如果报构建缓存 `Access is denied` 之类的错，先设一次缓存目录：`$env:GOCACHE = "$env:TEMP\gocache"`。

## 为什么要留代码

第 9-10 月要练 Hot 100，到时候真正值钱的是"我当时卡在哪、怎么错的"，不是当时 AC 的结果。代码和自测是那份记忆的载体。
