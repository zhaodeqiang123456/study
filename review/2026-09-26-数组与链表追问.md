# 408 书面作答 · 2026-09-26 · 数组与链表追问

**题目**：
1. 动态数组扩容代价为 O(n)，为什么末尾追加的平均代价是 O(1)？
2. 链表删除是 O(1) 还是 O(n)？
3. 数组和链表遍历都是 O(n)，为什么实际速度不同？

## 一、作答（限时 8 分钟）

**1. 结论**

动态数组单次扩容可能需要 O(n) 的元素复制，但连续进行 n 次追加时，所有扩容复制的总次数仍然是 O(n)，所以平均到每次追加是 O(1)。链表删除是否为 O(1)，取决于是否已经知道待删除节点的前驱；已知前驱是 O(1)，只知道节点值则需要先查找，整体是 O(n)。数组和链表遍历的渐进复杂度都是 O(n)，但数组连续存储、缓存命中率高，实际通常比链表快。

**2. 原因 / 机制**

动态数组容量通常按倍数增长。假设容量依次为 1、2、4、8，那么扩容时复制的元素数量是：

`1 + 2 + 4 + ... + 2^k < 2n`

因此，插入 n 个元素时，扩容复制总量是 O(n)，再加上 n 次普通插入，总操作量仍是 O(n)，平均每次追加就是 O(1)。但某一次刚好触发扩容的追加操作仍然可能花费 O(n)，所以这是摊还复杂度，不是每次都严格 O(1)。

链表删除时，如果已经拿到前驱节点，只需要修改前驱的 next 指针，因此是 O(1)。如果只知道要删除的值，就必须从头遍历链表寻找目标节点和它的前驱，查找过程需要 O(n)，所以整体是 O(n)。

数组元素连续存储，遍历时可以顺序读取，处理器容易利用缓存和预取。链表节点可能分散在内存中，每次访问都要读取 next 指针，容易发生缓存未命中，因此实际速度较慢。

**3. 对比与边界**

“数组追加平均 O(1)”不等于“每次追加都是 O(1)”；扩容那一次仍然是 O(n)。如果容量增长很慢，扩容次数增多，摊还性能也会变差。

“链表删除 O(1)”的前提是已经拿到前驱节点，或者某些情况下已经拿到待删除节点本身。若只有目标值，就必须先遍历查找，不能直接说是 O(1)。如果删除的是尾节点，即使知道尾节点，也可能还需要找到前驱，单链表仍可能需要 O(n)。

数组和链表遍历都是 O(n)，但大 O 复杂度忽略了缓存、指针跳转、内存分配等常数因素，所以不能只根据渐进复杂度判断实际性能。

**4. 场景**

例如日志记录不断追加到末尾时，动态数组通常更合适，因为追加的摊还复杂度是 O(1)，而且连续内存让遍历和统计速度较快。

如果一个任务队列经常在已知节点位置插入和删除任务，并且不需要按下标随机访问，链表可以通过修改指针以 O(1) 完成插入和删除。但如果主要操作是遍历、按下标读取或连续扫描，数组通常更合适。

## 二、对照复盘

- 对照标准答案，漏掉的点：需要明确“摊还 O(1)”和“单次扩容 O(n)”的区别；链表删除复杂度取决于是否知道前驱；还要说明缓存局部性。
- 写得含糊、自己也没底的点：动态数组的扩容倍数不同，具体复制次数会不同，但只要按倍数增长，追加通常可以摊还为 O(1)。
- 面试官会追问的 1-2 个问题：
  - 问：如果只拿到链表待删除节点本身，能否 O(1) 删除？
    答：如果不是尾节点，可以把后继节点的数据复制到当前节点，再跳过后继节点；如果是尾节点，没有前驱指针时仍然无法直接删除。
  - 问：为什么链表 O(1) 删除不一定比数组快？
    答：链表虽然少了搬移元素，但节点访问可能缓存不命中，还需要额外的指针和内存分配，实际可能更慢。
- 补充：复杂度必须结合“已经掌握了什么信息”来判断，不能脱离前提直接给结论。
- 一句话版本：动态数组追加靠扩容摊还到 O(1)，链表删除只有在已知位置时才是 O(1)，数组遍历通常因连续内存和缓存局部性更快。
