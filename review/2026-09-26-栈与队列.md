# 408 书面作答 · 2026-09-26 · 栈与队列

**题目**：
1. 用数组实现队列，如果出队就把后面所有元素往前挪，代价是什么？环形数组怎么避免？
2. 环形数组怎么区分"队空"和"队满"？说出两种做法及各自代价。
3. 栈为什么通常用数组实现？什么场景必须用链表？

## 一、作答（限时 8 分钟）

**1. 结论**

如果数组队列每次出队都把剩余元素向前搬移，单次出队可能是 O(n)；环形数组用 head 和 tail 两个下标取模，让入队和出队通常都是 O(1)。栈在同一端进行后进先出操作，动态数组适合在尾部完成 push 和 pop；链表适合元素数量变化大、且已经知道插入或删除位置的场景。

   1. 每次出队的时间复杂度为o(n) ， 环形数组可以通过牺牲一个存储位或者增加一个标志位
   2. 对于牺牲一个存储位的方式来说，当（队尾 +1） mod size == 队首时，队满， 对于有标志位的方式，每次操作都标识是进队还是出队
   3. 因为数组出栈入栈的时间复杂度为o(1)

**2. 原因 / 机制**

普通数组队列出队时，如果把剩余元素前移，需要复制剩余元素，复杂度为 O(n)。环形数组不搬移元素，而是令 head 和 tail 在数组末尾后回到下标 0，即 `next = (index + 1) % capacity`，所以每次只修改下标。

区分队空和队满有两种常见设计：一是浪费一个位置，规定 `head == tail` 为空、`(tail+1)%capacity == head` 为满，此时可用容量是 capacity-1；二是额外维护 size，`size == 0` 为空、`size == capacity` 为满，容量全部可用但需要维护 size。

数组栈只在尾部操作，push 平均 O(1)、pop O(1)，并且连续存储，缓存访问效率高。链表栈头部插入和删除也是 O(1)，但节点有额外指针且可能分散在内存中，常数通常更大。


**3. 对比与边界**

环形数组的 O(1) 不包含扩容那一次；底层数组扩容时仍要分配新空间并复制元素，单次是 O(n)，倍增策略下连续操作的均摊复杂度为 O(1)。链表插入删除只有在已知位置或前驱时才是 O(1)，如果还要先查找，整体仍是 O(n)。


**4. 场景**

浏览器历史回退可以用栈，打印任务按提交顺序处理可以用队列。若普通数组队列出队时搬移元素，任务很多会产生大量复制；环形队列可以避免这种开销。若编辑器频繁在已知位置插入删除节点，链表可能合适；若主要是遍历和按下标访问，数组更合适。
