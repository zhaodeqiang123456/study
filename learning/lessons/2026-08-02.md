## 1. 前置知识与术语

错误值是控制流的一部分；错误消息是给人看的，错误类型/哨兵值才是给程序判断的。`fmt.Errorf("...: %w", err)` 建立错误链，`errors.Is` 判断链上是否包含目标，`errors.As` 提取特定类型。

这对应 408 中的分层与抽象边界：底层驱动错误不应直接泄漏成 API 合同，服务层要把“可重试、冲突、未找到、内部故障”等语义分类。

## 2. 最小 Go 示例（对应题 1）

```go
var ErrNotFound = errors.New("not found")

func loadTask() error {
	return fmt.Errorf("task store: %w", ErrNotFound)
}

// errors.Is(loadTask(), ErrNotFound) == true
```

不要用字符串比较判断错误；包装后文本可能改变，但语义身份应保持。

## 3. 项目边界（对应题 2、3）

`TaskStore`/DB 层返回可识别的领域错误；service 层决定是否重试、记录哪些字段；HTTP 层映射为状态码和稳定错误码。日志应保留根因和 request/task ID，但响应不应暴露 SQL、Kafka broker 或内部堆栈。

## 4. 不变量、失败模式与取舍

- 同一领域错误在包装后仍可由 `errors.Is/As` 识别。
- API 状态码由服务契约决定，不随底层错误文本漂移。
- 只对明确幂等且可重试的错误重试；未知错误默认不重试。

常见失败：`err.Error()` 字符串匹配、丢失 `%w`、把所有错误返回 500、把客户端输入错误记录为系统故障、重试带来重复写入。

## 5. 面试追问与验证

追问“为什么不用字符串比较”“哪些错误可重试”“错误链如何跨层保留”。最小验证是 table-driven 测试：包装后 `errors.Is`、`errors.As`、HTTP 状态映射和未知错误默认 500。
