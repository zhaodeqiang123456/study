# Go 后端实习学习路线

> 目标：面向研二暑期后端实习，用 16 周完成“语言基础 -> 并发与标准库 -> 数据与分布式组件 -> 可展示项目 -> 面试复盘”的闭环。
>
> 起点：已有 408 基础，现有笔记覆盖 Go 基础语法、goroutine/channel、MySQL、Redis、Kafka、Qdrant，并已有一个 Go 项目。当前主要短板不是“看过的知识量”，而是正确性验证、工程化实践、性能证据和系统化复盘。

## 1. 执行原则

1. 每周最多 5 个目标；每个目标必须绑定可检查的验收产物，不能以“看完、理解”作为完成标准。
2. 学习比例建议为：项目 45%、Go/后端专题 25%、算法 20%、复盘 10%。课程繁忙时缩小范围，但保留项目、算法、复盘三个闭环。
3. 所有 Go 代码至少通过 `gofmt`、`go vet ./...`、`go test ./...`；并发代码额外执行 `go test -race ./...`。
4. 新知识采用“概念 -> 最小实验 -> 项目应用 -> 面试表达”四步法。笔记必须包含失败模式，不只记录 API。
5. 项目变更保持小步、可回滚；涉及接口、数据库或消息时，明确兼容性、事务、幂等、超时、可观测性和回滚方式。
6. 每周用证据说话：测试输出、benchmark、pprof、执行计划、压测数据、故障演练记录或设计文档至少一项。

## 2. 固定周节奏

| 时间 | 内容 | 最低产物 |
|---|---|---|
| 周一 10:00 | 依据上周复盘制定本周计划 | 当周计划，最多 5 个目标，每项含验收物 |
| 每天 17:30 | 45 分钟刻意训练 | 题目、作答记录、错误分类、下一步 |
| 周三 21:30 | 中期检查，只诊断不改代码 | 阻塞清单、需要缩小的范围 |
| 周日 20:00 | 汇总并复盘 | Git 证据、错题、笔记、薄弱项、下周建议 |

45 分钟训练结构：5 分钟回忆旧错题，25 分钟独立作答，10 分钟运行测试或手工验证，5 分钟记录错误类型。出题时不提供答案；完成后再对照测试和提示订正。

## 3. 16 周路线

### 阶段一：Go 基础校准（第 1-3 周）

#### 第 1 周：语法、数据模型与工具链

- 内容：package/module、变量与类型、数组/slice/map、struct、指针、函数、defer、错误处理、Go 命令与项目布局。
- 工程重点：slice 共享底层数组、map 非并发安全、零值、值语义与指针语义、错误包装与 `errors.Is/As`。
- 验收产物：
  - `learning/exercises/basics/` 下不少于 8 个小练习及表驱动测试；
  - 一份“slice 扩容与别名问题”实验，包含测试输出；
  - 运行 `gofmt`、`go vet ./...`、`go test ./...` 的记录。

#### 第 2 周：方法、接口、泛型与可测试设计

- 内容：method set、pointer/value receiver、隐式实现、接口组合、nil interface、type assertion、泛型约束。
- 工程重点：接口由消费者定义，小接口优先；避免为 mock 预先制造大接口；理解 typed nil。
- 验收产物：
  - 把一个依赖外部存储的组件改造成可替换实现；
  - fake 实现与表驱动单元测试；
  - 一页接口设计说明，能回答 method set、typed nil、接口与泛型取舍。

#### 第 3 周：标准库与 HTTP 服务基础

- 内容：`io`、`bufio`、`encoding/json`、`net/http`、`time`、`log/slog`、配置与错误边界。
- 工程重点：HTTP 超时、请求体大小限制、状态码、统一错误响应、结构化日志、优雅关闭。
- 验收产物：
  - 一个含 CRUD/健康检查的最小 HTTP 服务；
  - `httptest` 覆盖成功、非法输入、依赖失败和超时；
  - API 示例及错误码表。

### 阶段二：并发与运行时（第 4-6 周）

#### 第 4 周：goroutine、channel 与所有权

- 内容：goroutine 生命周期、无缓冲/缓冲 channel、close、range、select、fan-out/fan-in、worker pool。
- 必答问题：谁创建和关闭 channel，谁拥有 goroutine，消费者变慢时如何背压，错误如何返回。
- 验收产物：
  - 有界 worker pool，支持错误传播和停止；
  - goroutine 泄漏测试或可重复的泄漏演示；
  - `go test -race ./...` 通过记录。

#### 第 5 周：context、取消与服务生命周期

- 内容：`context.Context` 的 deadline/cancel/value、取消传播、`signal.NotifyContext`、超时预算。
- 工程重点：`Context` 作为首参数，不存入 struct；所有阻塞点响应取消；区分客户端取消、内部超时和业务错误。
- 验收产物：
  - HTTP -> service -> DB/Redis/Kafka 的取消链路图；
  - 超时、主动取消、优雅关闭三类测试；
  - 一份 goroutine 生命周期清单，确认无后台任务失管。

#### 第 6 周：共享内存、调度与性能

- 内容：Mutex/RWMutex/atomic/Once/WaitGroup、Go memory model、G-M-P、逃逸分析、benchmark、pprof。
- 工程重点：先证明有竞争再加锁；比较 channel 与 mutex 的适用边界；避免无界并发。
- 验收产物：
  - 一个数据竞争复现及两种修复对比；
  - 至少 2 个 benchmark，含 `benchstat` 或前后数据；
  - CPU 或 heap profile 与一项有数据支持的优化。

### 阶段三：算法与后端基础并进（第 7-10 周）

#### 第 7 周：算法模板与复杂度表达

- 内容：数组/链表、哈希、栈队列、二分、双指针、滑动窗口；复习时间/空间复杂度。
- 验收产物：
  - 12 道题，至少 3 类模板；
  - 每道错题记录错误类型、反例、复杂度与二刷日期；
  - 随机选 2 题在 25 分钟内口述并编码。

#### 第 8 周：树、堆、图与搜索

- 内容：二叉树 DFS/BFS、堆、并查集、拓扑排序、最短路基础、回溯。
- 验收产物：
  - 12 道题及二刷结果；
  - 4 个可复用 Go 模板及测试；
  - 一份“递归栈与 goroutine 栈不是同一概念”的说明。

#### 第 9 周：MySQL 与事务

- 内容：索引/B+ 树、联合索引、执行计划、事务、MVCC、隔离级别、锁、连接池。
- 工程重点：参数化 SQL、`QueryContext`、事务边界、唯一约束保证幂等、慢查询观测。
- 验收产物：
  - 项目核心查询的 `EXPLAIN` 前后对比；
  - 事务回滚、并发更新、幂等写入的集成测试；
  - 数据模型和索引选择说明。

#### 第 10 周：Redis 与 Kafka

- 内容：缓存一致性、穿透/击穿/雪崩、热点 key；Kafka 分区、副本、消费组、offset、重试和重复消费。
- 工程重点：缓存不是事实源；本地 mutex 不能解决多实例击穿；消息至少一次语义要求消费者幂等。
- 验收产物：
  - cache-aside 实现及缓存失效/并发回源测试；
  - Kafka 消费者幂等与失败重试演示；
  - 一份故障矩阵：Redis/Kafka/DB 超时或不可用时服务行为。

### 阶段四：项目工程化（第 11-14 周）

以 `project/` 为主项目，不重开纯练手项目。先为现状建立基线，再逐步改造；Qdrant/RAG 只在主链路稳定后加深，避免技术栈堆砌。

#### 第 11 周：架构基线与契约

- 内容：梳理入口、领域逻辑、存储、Kafka、Redis、Qdrant/LLM 边界；定义 API 和依赖方向。
- 验收产物：
  - 架构图、关键时序图、ADR 至少 1 份；
  - 当前测试覆盖和基准性能基线；
  - 风险清单及分阶段回滚方案。

#### 第 12 周：可靠性

- 内容：超时、重试、退避、幂等、事务一致性、限流、背压、优雅关闭。
- 验收产物：
  - 一个端到端关键链路及集成测试；
  - 重复请求、重复消息、依赖超时、进程退出四类故障测试；
  - 明确哪些错误可重试、重试上限和副作用。

#### 第 13 周：可观测性

- 内容：结构化日志、request/trace ID、RED 指标、runtime 指标、profiling、告警思路。
- 验收产物：
  - 日志字段规范；
  - 延迟、流量、错误率及队列/连接池指标；
  - 一次从告警现象定位到根因的演练记录。

#### 第 14 周：性能与容量

- 内容：负载模型、p50/p95/p99、吞吐、饱和点、连接池、分配优化、限流与降级。
- 验收产物：
  - 可重复的压测脚本和环境说明；
  - 优化前后数据表及 profile；
  - 容量结论：单实例目标负载、瓶颈、保护阈值，不只写平均延迟。

### 阶段五：面试表达与总复盘（第 15-16 周）

#### 第 15 周：系统设计与项目讲解

- 内容：需求澄清、容量估算、API/数据模型、缓存、消息、扩展性、一致性、故障恢复、安全。
- 验收产物：
  - 2 道 45 分钟系统设计题；
  - 5 分钟与 15 分钟两个版本的项目讲解；
  - 10 个追问及基于真实证据的答案。

#### 第 16 周：模拟面试与缺口收敛

- 内容：Go、并发、OS/网络、MySQL/Redis/Kafka、算法、项目交叉模拟。
- 验收产物：
  - 2 次完整模拟面试记录；
  - 高频失分点清单和定向二刷；
  - 项目 README/架构/测试/压测材料完整，可在新环境按文档启动。

## 4. 持续算法计划

- 每周 6-10 题，以质量为先；新题约 60%，错题二刷约 40%。阶段三集中周可提升到 12 题。
- 错误类型固定为：题意遗漏、边界错误、模板不熟、复杂度失控、数据结构选择错误、实现 bug、Go 语言陷阱、表达不清。
- 错题记录至少包含：题目链接/名称、首次用时、错误原因、最小反例、正确复杂度、二刷日期、是否能口述。
- 面试标准：先澄清输入和边界，再讲朴素方案与优化，最后编码并用反例验证；不要背代码模板而无法解释不变量。

## 7. 阶段性退出标准

- Go：能解释接口 method set、typed nil、slice/map 语义、错误链，并用测试复现常见陷阱。
- 并发：任何设计都能说清 ownership、race、cancellation、goroutine lifetime、backpressure 和 error propagation。
- 后端：能以真实代码解释 API 兼容、事务、幂等、超时、可观测性、安全和回滚。
- 算法：常见中等题能在 25-35 分钟内完成，能够给出复杂度和边界证明。
- 项目：有架构图、测试、故障演练、benchmark/profile、压测数据，且能回答“为什么这样设计”和“哪里会失败”。
- 复盘：连续 4 周有可核验产物；若只积累笔记而没有代码或测量结果，视为未达标。

## 8. 推荐的一手资料

- Go 官方教程与规范：A Tour of Go、Effective Go、Go Language Specification。
- Go 官方工程资料：Go blog、Go Code Review Comments、标准库文档与 examples。
- 并发：Go Memory Model、`context`/`sync`/`runtime`/`net/http` 包文档。
- 工具：`go test`、race detector、benchmark、fuzzing、`go tool pprof`、execution tracer。
- 算法：按数据结构与解题模式归类，不以连续刷题天数替代错题复盘。

资料用于校验概念，项目代码、测试结果和性能数据才是最终验收依据。
